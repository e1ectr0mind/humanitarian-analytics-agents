# Дизайн: Реестр индикаторов + агент-дизайнер XLSForm (подпроект 3)

**Дата:** 2026-09-08
**Статус:** утверждён (секции 1–3 согласованы в брейншторм-сессии)
**База:** ядро (подпроект 1) + коннекторы/чистильщик (ломоть 2а) — реализованы, master

---

## 1. Контекст и решения брейншторма

Подпроект 3 платформы («Проектный контекст и формы»): структурированный реестр
индикаторов + третья агентская роль — дизайнер форм опроса (XLSForm для
Kobo/Ona).

Ключевые решения:

- **Деплой форм на сервер — НЕ входит.** v1 производит провалидированный
  `.xlsx`; пользователь загружает его в Kobo/Ona одним кликом в UI.
  (Коннекторы остаются read-only; write-возможность — отдельным ломтём позже.
  Это осознанная поправка к фразе платформенной спеки «загрузка через
  коннекторы подпроекта 2».)
- **Реестр — гибрид:** описательная база (код, название, определение, цель,
  дезагрегации, источник) + ОПЦИОНАЛЬНЫЙ машиночитаемый блок `measure`.
  Расчёт индикаторов в v1 — через аналитика, ведомого `measure`-спекой;
  детерминированный движок — позже, схема уже готова.
- **Формы двуязычные по умолчанию:** `label::Українська (uk)` +
  `label::English (en)` для каждого вопроса и варианта ответа.
- **Дизайнер создаёт новые формы И правит локальные** (лежащие в workspace).
  Импорт чужих форм с сервера — не в этом ломте.
- **Архитектура «модель + рендерер»:** источник истины — машиночитаемая
  модель формы (`*.form.yaml`), `.xlsx` всегда детерминированно рендерится
  из неё и никогда не редактируется на месте. Каждый save прогоняет pyxform.

## 2. Цели и границы

**Возможность 1 — реестр индикаторов** `workspace/indicators.yaml`.
Появление: «извлеки индикаторы из логфрейма» → оркестратор → дизайнер →
чтение `project_docs/` → YAML → `save_indicators` (детерминированная схемная
валидация). Пользователь может править файл руками. Аналитик получает
`read_indicators` и опирается на реестр в вопросах о прогрессе к целям.

**Возможность 2 — дизайнер форм.** Диалог («сделай форму PDM по индикаторам
1.1 и 2.1, добавь блок согласия») → модель формы → `save_form` → пара
артефактов: `workspace/forms/<имя>.form.yaml` (источник истины) и
`workspace/forms/<имя>.xlsx` (рендер, готов к ручной загрузке). Каждый
`save_form` компилирует форму pyxform; ошибки возвращаются агенту дословно.
Правка: `load_form` → изменение модели → `save_form` (полный ре-рендер).

**Дисциплина дизайнера (промпт):** согласие в начале формы; SADD-поля
(пол/возраст/инвалидность респондента), когда дезагрегации индикаторов их
требуют; стабильные `list_name`; никаких лишних PII-вопросов без обоснования;
вопросы формы должны собирать данные, из которых индикаторы вычислимы.

**Не входит:** деплой на серверы, импорт форм с Kobo/Ona, детерминированный
движок расчёта индикаторов, каскадные выборы (область→район), медиа-вопросы.

## 3. Архитектура и компоненты

```
src/haa/
├─ forms/                      ← НОВОЕ: чистая логика, ноль LLM
│  ├─ model.py                 ← FormModel/Group/Question/Choice +
│  │                              validate_model(dict) → список ошибок
│  ├─ renderer.py              ← render_xlsx(model, path): survey/choices/
│  │                              settings, label::Українська (uk)/English (en)
│  ├─ compiler.py              ← compile_check(xlsx) → вердикт pyxform
│  └─ storage.py               ← load/save *.form.yaml (workspace/forms/)
├─ indicators/registry.py      ← схема реестра + load/save indicators.yaml
├─ core/
│  ├─ tools/formtools.py       ← третий MCP-сервер "forms" (5 инструментов)
│  ├─ agents/designer.py       ← DESIGNER_PROMPT + build_designer
│  ├─ agents/registry.py       ← + designer (три роли)
│  ├─ agents/orchestrator.py   ← маршрутизация: формы/индикаторы → designer
│  └─ session.py               ← проводка forms-сервера; analyst += read_indicators
└─ config.py                   ← + designer_model; свойство forms_dir
```

**Инструменты сервера `forms`:** `save_form(name, model_yaml)` (схема → yaml
на диск → рендер xlsx → pyxform → вердикт), `load_form(name)`,
`list_local_forms()`, `read_indicators()`, `save_indicators(yaml_text)`.

**Доступы ролей:** designer = forms-инструменты + `list_project_docs` +
`read_project_doc` + `list_datasets` + `profile_dataset` (без `run_analysis`);
analyst += `mcp__forms__read_indicators`; cleaner без изменений.

**Схема модели формы** (`*.form.yaml`):

```yaml
title: {uk: "…", en: "…"}
form_id: pdm_2026
groups:
  - name: consent
    label: {uk: "…", en: "…"}
    questions:
      - name: consent_given
        type: select_one     # text|integer|decimal|date|note|geopoint|
                             # select_one|select_multiple
        list: yesno          # обязателен для select_*
        label: {uk: "…", en: "…"}
        required: true
        relevant: null       # опц. XLSForm-выражение
        constraint: null     # опц.
        hint: null           # опц. {uk, en}
choices:
  yesno:
    - {name: "yes", label: {uk: "Так", en: "Yes"}}
```

**Схема реестра** (`indicators.yaml`):

```yaml
indicators:
  - code: "1.1"
    name: {uk: "…", en: "…"}
    definition: "…"
    target: {value: 2500, unit: households}
    disaggregation: [sex, oblast]
    source: beneficiaries
    measure:                  # опционально
      dataset: beneficiaries
      aggregation: count_unique   # count|count_unique|sum|percent
      field: _uuid
      filter: null                # опц. pandas-query
      # для aggregation: percent — вместо field/filter два под-блока
      # numerator: {field, filter} и denominator: {field, filter}
```

Поле `version` формы модель НЕ содержит — рендерер проставляет его
автоматически (timestamp `YYYYMMDDHHMM`) в лист settings при каждом рендере,
чтобы Kobo корректно распознавал обновления при повторной загрузке.

Валидация обеих схем детерминированная, ошибки адресные
(«indicators[2].target.value: ожидается число»). `.xlsx` только
пересобирается из модели. PII-граница не затрагивается (`forms_dir` вне
`data_dir`; реестр и формы — не данные бенефициаров). Новая зависимость:
`pyxform`.

## 4. Потоки

**Извлечение индикаторов:** дизайнер читает документацию (+ при желании
`profile_dataset` для привязки `source`/`measure.field` к реальным колонкам)
→ YAML → `save_indicators`; ошибка валидации → правка → повтор (лимиты — от
ядра). Ответ: сколько индикаторов, у скольких цель, у скольких `measure`.

**Создание формы:** при необходимости `read_indicators` → модель →
`save_form` → схема → рендер → pyxform → вердикт; ошибки компиляции (дубль
имени, битое relevant, ссылка на отсутствующий list) дословно агенту →
правка → повтор. Успех: путь к xlsx, число групп/вопросов, языки,
напоминание про ручную загрузку.

**Правка:** `load_form` → изменение модели → `save_form` (ре-рендер целиком).

**Телеметрия:** события `indicators_saved` (count, with_measure) и
`form_saved` (имя, вопросов, число неудачных попыток до успеха).

## 5. Обработка ошибок

| Ситуация | Поведение |
|---|---|
| битый YAML от агента | парс-ошибка с номером строки, дружелюбно |
| неизвестный тип вопроса / ссылка на отсутствующий список / дубль имени | адресные схемные ошибки списком |
| ошибка pyxform | вердикт дословно (это язык, понятный агенту) |
| `read_indicators` до первого извлечения | «реестр пуст, попросите извлечь индикаторы из логфрейма» |
| правка несуществующей формы | сообщение со списком локальных форм |
| всё прочее | паттерн 2а: дружелюбные строки, не трейсбеки |

## 6. Тестирование

- **Офлайн (масса):** валидация модели (позитив + каждый класс ошибок);
  golden-тест рендерера (модель → xlsx → чтение openpyxl → точные
  колонки/языки/строки); **компиляция pyxform реального отрендеренного
  примера** (двуязычная форма с группами, select'ами, relevant — главный
  тест среза, без LLM); storage round-trip; схема реестра; formtools
  (методы напрямую, паттерн DataToolbox); проводка сессии; роль/маршрутизация.
- **API-эвалы (2, ручные, метка `api`):** «извлеки индикаторы из
  демо-логфрейма» → реестр содержит 1.1 с target 2500 (ожидания посчитаны
  в тесте из логфрейма независимо); «сделай форму по индикаторам» → xlsx
  существует, компилируется pyxform в тесте, содержит SADD-вопросы и оба
  языка.
- CI без изменений.

## 7. Критерии приёмки

1. «Извлеки индикаторы из логфрейма» (на демо) → `workspace/indicators.yaml`
   проходит схему, содержит индикатор 1.1 с целью 2500.
2. Аналитик отвечает на «как прогресс к 1.1?» с использованием
   `read_indicators` (видно по телеметрии), число совпадает с независимым
   расчётом.
3. «Сделай форму …» → `forms/<имя>.form.yaml` + `forms/<имя>.xlsx`;
   xlsx компилируется pyxform; оба языка присутствуют; есть согласие и
   SADD-поля.
4. «Сделай вопрос X необязательным» на существующей локальной форме →
   модель обновлена, xlsx пересобран, pyxform зелёный.
5. События `indicators_saved`/`form_saved` в телеметрии.
6. Офлайн-тесты и ruff зелёные в CI; api-эвалы проходят локально.
